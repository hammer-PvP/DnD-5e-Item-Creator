# Character Builder automation integration — Item Creator 0.6.0

Item Creator treats Character Builder's published coordination APIs as the canonical cross-module contract. The integration does not make Character Builder a hard dependency: when a compatible API is absent, Item Creator keeps its existing standalone runtime.

## Shared Roll Resolution Queue v3

Compatibility gate:

```js
const queue = game.modules.get("dnd5e-character-builder")?.api?.rollResolutionQueue;
const compatible = queue?.version >= 3
  && queue?.capabilities?.discoveryBarrier === true
  && queue?.capabilities?.dynamicPriorityDrain === true;
```

Canonical order: `D&D5e native → Character Builder (200) → Item Creator (300) → lifecycle`.

For a possible asynchronous post-roll Item provider:

1. `claim()` synchronously from the native roll hook, before the first `await`.
2. Discover Item Creator eligibility without consulting hidden outcome data.
3. If there is no eligible modifier, release the claim.
4. Otherwise enqueue one provider in phase `items` / priority `300`, then release the discovery claim.
5. Keep the provider Promise open through all sequential Item Creator `Use / Keep` decisions.
6. Return the final Item-phase `currentTotal` and only the Item Creator adjustments generated by that provider.
7. Never call `finalize()` or `requestFinalization()` from ordinary Item providers.

Concentration is still owned by D&D5e/Character Builder lifecycle. Item Creator treats the roll as a Saving Throw for its own eligibility but preserves the shared queue identity `concentration` when that identity already exists.

## Resource Events v1

Compatibility contract:

```js
const events = game.modules.get("dnd5e-character-builder")?.api?.resourceEvents;
const compatible = events?.protocol === "dnd5e-resource-events"
  && events?.version >= 1
  && typeof events?.subscribe === "function";
```

When compatible, this protocol is the only authority for Resource Consumed semantics:

- `payload.resource`: the resource that actually changed.
- `payload.cause`: the Item/Activity responsible for the transaction.

Item Creator correlates the event with native `postUseActivity` to retain Usage Message targets. It does not use that context to guess or replace `payload.resource`. The legacy `results.updates` detector is disabled while Resource Events v1 is authoritative.

`Specific Resource Spent` therefore matches the resource. `Specific Feature Used` remains a distinct trigger matching the Feature/Activity use. No behavior is keyed to names such as Bardic Inspiration or Cutting Words.

## Privacy boundary

Item Creator may carry internal queue target/outcome data for coordination and GM-only reporting, but it must not use hidden AC, DC, hit/miss, Success/Failure, or an inferred adjudication to decide whether a player-facing modifier prompt is offered.

## Ownership boundary

- D&D5e owns native roll/casting/concentration mechanics.
- Character Builder owns the shared queue contract and its character-origin lifecycle/providers.
- Item Creator owns Item-origin eligibility, Triggered Effects, consumption, duration, stacks, target recipients, and its own UI.
- Item Creator does not create a parallel global lifecycle or roll-finalization service.
